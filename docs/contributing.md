# 协作与文档维护

本仓库可能有内容、界面、工装等多个窗口共享同一工作树。协作重点不是“谁的文件更多”，而是确保每次提交只包含自己能够解释的改动。

## 开始前

1. 阅读 [项目结构](project-structure.md)，确认文件是真源、生成物、测试还是历史留档。
2. 运行 `git status --short` 和必要的 `git diff`，识别其他窗口的在途改动。
3. 修改词表或例句前阅读[数据与生成流水线](data-pipeline.md)；修改测试前阅读[测试与巡检](testing.md)。
4. 不要为了让基线“干净”而 `checkout`、`reset` 或删除不属于自己的文件。

## 暂存与提交边界

- **不要 `git add -A`**。只暂存本轮真正修改且已核对的路径。
- 暂存前再次查看状态；显式路径暂存也不能替代检查该文件是否混有他人改动。
- 共享文件存在他人未提交改动时，先协调提交顺序，或只隔离自己的补丁；不要整文件覆盖、整文件还原。
- 生成物必须与真源在同一逻辑改动中同步，不要只提交一半流水线。
- 提交前核对 diff，运行与改动面匹配的测试，并在提交信息中写明实跑结果或未跑项。

提交信息采用可检索的中文结构：

```text
域(主题)：具体改动与关键结果
```

避免只写 `update`。涉及词数、分类数或核心层变化时，在提交信息中写明前后数字。

## 临时产物生命周期

巡检截图、量宽探针、调试副本这类中间产物**一律不入库**（相关路径已由 `.gitignore` 排除），并按下面约定控制堆积：

1. **巡检截图进带轮次或域名的子目录**：`tools/_shots/<轮次或域名>/`，不要散落在根目录或混用多个目录。
2. **轮次收尾即清**：节正文与提交信息写明关键实测数字后，该轮的截图与探针就失去留档价值，随手删除；不留“以后可能用”的副本——要复现就重跑巡检。
3. **确实要跨会话交接的判据与候选表**放 `tools/_audit/`（体积小、可检索），不与截图混放；入库前先核对是否属于本轮写面。
4. **清理前必须确认并发窗口空闲**：`tools/_tmp/`、`shots/`、`tools/_shots/` 可能正被别的窗口写入（看文件修改时间）。有新写入就等，不要凭目录名判断“看起来没人用”。
5. **全量回收只做一件事**：确认空闲后删除整个临时目录，而不是逐个挑选——挑漏的文件正是下轮的假基线来源。

历史上这些目录一度堆积约 41 MB；约定生效后应在轮次收尾时归零，而不是等集中清理。

## CHANGELOG 追加规则

1. **历史正文不改写**。历史节是当时的快照；新结论追加新节，当前状态在文首更新。
2. 落笔前实读文件末尾和全部二级标题，取当前最大编号再加一。不要按记忆取号，也不要按“已有节数 + 1”取号——历史上有重号与缺号。
3. 新增节后同步文首“记录进度”的三个实测量：
   - `^## ` 标题行数；
   - 编号节数量；
   - 最大节号。
4. 保留历史缺号与“十七”重号，不为追求连续而重排旧节。
5. 文首目录若不能完整维护，应明确它是历史导航，不让读者误以为覆盖全部后续章节。
6. 记录验证结果时区分“已实跑通过”“未运行”“环境不具备”，不要把静态推断写成测试通过。

## 当前文档的写法

文档导航与归属见[文档索引](README.md)。维护时遵守：

- 当前事实只在主要归属文档中详写，其他位置给摘要和链接；
- 不把 CHANGELOG 的历史数字复制进新文档；
- 词数、分类数、例句数等派生数字从当前产物实跑取得；
- 测试断言总数以实跑输出为准，不在说明里制造需要逐轮维护的字面量；
- 移动文件后检查 Markdown 相对链接和脚本路径；
- 文档中的命令从仓库根目录执行，路径与真实文件名保持一致。

### 常见同步面

| 变化 | 同步位置 |
|---|---|
| 功能或快捷键 | README 概览、[使用指南](user-guide.md)、必要的页面内帮助 |
| 词库规模或分类口径 | README、CHANGELOG 当前状态、[数据与生成流水线](data-pipeline.md)、页面静态文案 |
| 生成流程或真源变化 | [数据与生成流水线](data-pipeline.md)、[项目结构](project-structure.md) |
| 测试增删或职责变化 | [测试与巡检](testing.md)、[项目结构](project-structure.md) |
| 文件移动或临时目录规则变化 | [项目结构](project-structure.md)、`.gitignore`、所有引用方 |

## 完成前检查

```bash
git status --short
git diff --check
git diff --stat
```

再根据改动面运行测试。文档改动至少检查本地相对链接；数据改动运行完整生成与回归链；前端改动运行对应 DOM、浏览器、无障碍或版面测试。

最后确认：

- 没有误暂存截图、临时目录或其他窗口的文件；
- 本轮自己的巡检截图与探针已按[临时产物生命周期](#临时产物生命周期)清理；
- 没有手改生成物来“修补”上游问题；
- 没有留下文档之间相互矛盾的数字与命令；
- CHANGELOG 新节编号来自落笔时的真实最大值。
